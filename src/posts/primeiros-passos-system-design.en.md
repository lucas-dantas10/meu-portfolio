Anyone who works with legacy systems knows well **how things break**. System Design teaches you to think about that *before* writing the first line.

## Questions I started asking

- How many users and how many requests per second do I expect?
- What happens if this service goes down for 10 minutes?
- Which data must be consistent right now, and which can lag a little?

## Differences I noticed

| At work | In interviews |
| --- | --- |
| The system already exists and has a history | You start from a blank page |
| A change has to be safe | A choice has to be justified |

I am still at the beginning, and I will update this post as I study more.
